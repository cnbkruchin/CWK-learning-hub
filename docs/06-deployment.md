# การติดตั้ง ใช้งาน สำรอง และกู้คืน

## 1. เตรียมบัญชีระบบ

1. ใช้ **บัญชี Google Workspace for Education ของโรงเรียนที่สร้างเฉพาะสำหรับระบบ** เช่น `learninghub@<โดเมนโรงเรียน>`
   - ข้อมูลและไฟล์ทั้งหมดอยู่ใน Drive ของบัญชีนี้ ไม่ผูกกับครูคนใดคนหนึ่ง
   - พื้นที่และโควตา Apps Script ของ Workspace สูงกว่าบัญชี Gmail ทั่วไป (บัญชีทั่วไปมีพื้นที่ 15 GB ซึ่งไม่พอสำหรับไฟล์งานทั้งโรงเรียน)
2. เปิดการยืนยันตัวตนสองชั้นให้บัญชีนี้ และจำกัดผู้ที่รู้รหัส
3. **ห้ามแชร์** โฟลเดอร์ `CWK Learning Hub — ข้อมูลระบบ (ห้ามแชร์)` และไฟล์ Sheets ใด ๆ ให้ผู้อื่น

## 2. นำโค้ดขึ้น Apps Script

### ทางเลือก ก: ใช้ clasp (แนะนำ)

```bash
npm install -g @google/clasp
clasp login                                   # ล็อกอินด้วยบัญชีระบบ
clasp create --type standalone --title "CWK Learning Hub" --rootDir gas
clasp push                                    # อัปโหลดทุกไฟล์ใน gas/ (รวม ui/*.html และ appsscript.json)
```

ถ้ามีโปรเจกต์อยู่แล้ว คัดลอก `.clasp.json.example` เป็น `.clasp.json` แล้วใส่ Script ID

### ทางเลือก ข: คัดลอกด้วยมือ

1. เปิด <https://script.google.com> → โปรเจกต์ใหม่ → ตั้งชื่อ
2. Project Settings → เลือก "Show appsscript.json manifest file in editor" → วางเนื้อหา `gas/appsscript.json`
3. สร้างไฟล์สคริปต์ชื่อเดียวกับไฟล์ `.js` ใน `gas/` (เช่น `Config`, `Db`, …) แล้ววางเนื้อหา
4. สร้างไฟล์ HTML ชื่อ `ui/Index`, `ui/Styles`, `ui/App` (พิมพ์ชื่อพร้อม `ui/`) แล้ววางเนื้อหา

## 3. ติดตั้งฐานข้อมูลและโฟลเดอร์

1. ใน editor เลือกฟังก์ชัน `setup` → Run → อนุญาตสิทธิ์ (Sheets, Drive, เรียก URL ภายนอก, trigger, อีเมลผู้ใช้)
2. ดู Execution log:
   - ลิงก์ไฟล์ฐานข้อมูล 6 ไฟล์ และรหัสโฟลเดอร์ราก
   - **ชื่อผู้ใช้ `admin` และรหัสผ่านชั่วคราว** (แสดงครั้งเดียว ต้องเปลี่ยนเมื่อเข้าใช้ครั้งแรก — อย่าคัดลอกเก็บไว้ที่อื่น)
3. เลือกฟังก์ชัน `installTriggers` → Run (งานรายชั่วโมง: ตรึงกลุ่ม ย้ายไฟล์ค้าง / รายวัน 02:00: ล้างไฟล์ สำรอง คำนวณพื้นที่)

`setup` รันซ้ำได้อย่างปลอดภัย: สร้างเฉพาะสิ่งที่ขาด เพิ่มคอลัมน์ใหม่ต่อท้าย ไม่ลบหรือย้ายข้อมูลเดิม
และตั้ง `ENV=production` ให้โปรเจกต์ (ห้ามใส่ข้อมูลสาธิต)

## 4. เผยแพร่เว็บแอป

Deploy → New deployment → ประเภท **Web app**

| ตัวเลือก | ค่าที่แนะนำ | เหตุผล |
| --- | --- | --- |
| Execute as | **Me** (บัญชีระบบ) | ผู้ใช้ไม่ต้องมีสิทธิ์ในไฟล์ใด ๆ ระบบตรวจสิทธิ์เอง |
| Who has access | **Anyone** | นักเรียนบางคนไม่มีบัญชี Google (ใช้รหัสนักเรียน + รหัสผ่านของระบบ) |
| | หรือ *Anyone within <โดเมน>* | ถ้าทุกคนมีบัญชี Workspace ของโรงเรียน (เพิ่มอีกชั้นป้องกัน) |

นำ URL ที่ลงท้าย `/exec` ไปแจกนักเรียนและครู (ทำเป็น QR code ได้)

**อัปเดตโค้ด**: `clasp push` → Deploy → Manage deployments → แก้ deployment เดิม → Version: New version (URL เดิม)
หาก `Schema.js` เปลี่ยน ให้รัน `setup` อีกครั้งหลัง push

## 5. ตั้งค่าเริ่มต้นหลังติดตั้ง

1. เข้าเว็บด้วย `admin` + รหัสชั่วคราว → ตั้งรหัสผ่านใหม่
2. หน้าผู้ดูแล: ตรวจพื้นที่ Drive, ตั้งขนาดไฟล์/จำนวนไฟล์/ชนิดไฟล์ที่อนุญาต/อายุการเก็บไฟล์
3. แก้ชื่อโรงเรียน/ชื่อระบบได้ในแถวของตาราง `schools` (หน้าจัดการโรงเรียนอยู่ในระยะถัดไป)
4. **ข้อมูลครู นักเรียน รายวิชา และการลงทะเบียน**: เครื่องมือนำเข้า (Import Wizard) อยู่ในระยะถัดไป —
   ระหว่างนี้ใช้ระบบสาธิตเพื่อทดลอง ไม่แนะนำให้พิมพ์ข้อมูลลงชีตโดยตรง เพราะข้ามการตรวจข้อมูลและรหัสผ่านต้องสร้างด้วยระบบ

## 6. ระบบสาธิต (แยกจากระบบจริง)

1. สร้าง **โปรเจกต์ Apps Script ใหม่อีกโปรเจกต์** (อย่าใช้โปรเจกต์ระบบจริง) แล้วนำโค้ดชุดเดียวกันขึ้น
2. รัน `setupDemo` → ได้โรงเรียนสาธิต ครู 3 คน นักเรียน 12 คน (รหัส `00121`–`00132`) รายวิชาที่เปิดสอน 3 กลุ่ม
   งานเดี่ยว งานกลุ่ม และการสอบ พร้อมบัญชีทดสอบและรหัสผ่านสุ่มใน log
3. หน้าเว็บของระบบสาธิตมีแถบ "ระบบสาธิต — ข้อมูลทั้งหมดเป็นข้อมูลสมมติ"

ฟังก์ชัน `setupDemo`/`seedDemo` ปฏิเสธการทำงานในโปรเจกต์ที่ตั้ง `ENV=production`

### ทดลองบนเครื่องโดยไม่ต้อง deploy

```bash
npm run dev          # http://localhost:8080 — ใช้โค้ดใน gas/ จริงกับบริการ Google จำลอง ข้อมูลอยู่ในหน่วยความจำ
npm test             # ทดสอบหน่วย/การทำงานร่วม 64 กรณี (บริการ Google จำลอง)
npm run test:e2e     # ทดสอบหน้าเว็บในเบราว์เซอร์ (ต้องมี Playwright + Chromium)
```

## 7. การกู้คืนข้อมูล

ชุดสำรองอยู่ที่ `08_backups/<YYYY-MM-DD_HHmmss>/` ประกอบด้วยสำเนา Sheets 6 ไฟล์และ `manifest.json`
(สำรองด้วยมือได้ด้วยฟังก์ชัน `backupNow`)

**ทดสอบคืนค่าบนสภาพแวดล้อมแยก (ควรทำทุกภาคเรียน)**
1. สร้างสำเนาโปรเจกต์ Apps Script (File → Make a copy) เป็นโปรเจกต์ทดสอบ
2. ใน Project Settings → Script properties ของโปรเจกต์ทดสอบ ตั้ง `DB_CORE`, `DB_PLAN`, `DB_WORK`, `DB_FILES`, `DB_GRADES`, `DB_SYSTEM`
   เป็นรหัสไฟล์ใน `manifest.json` ของชุดสำรอง และตั้ง `ENV=restore-test`
   (คัดลอก `FOLDER_*` และ `PEPPER` จากโปรเจกต์จริง — `PEPPER` ต้องตรงกันมิฉะนั้นรหัสผ่านเดิมใช้ไม่ได้)
3. Deploy เป็นเว็บแอปทดสอบ (Who has access: Only myself) ตรวจว่างาน รุ่น สมาชิกกลุ่ม และการเปิดไฟล์ยังสัมพันธ์กันครบ
   — **อย่าติดตั้ง trigger และอย่าอัปโหลด/ส่งงาน** ในโปรเจกต์ทดสอบ เพราะใช้โฟลเดอร์ไฟล์ชุดเดียวกับระบบจริง (ตรวจแบบอ่านอย่างเดียว)

**กู้คืนจริง**
1. ปิดการเข้าถึงชั่วคราว (Manage deployments → Archive หรือเปลี่ยน access เป็น Only myself)
2. คัดลอกไฟล์สำรองที่ต้องการ (Make a copy) ไปไว้ใน `01_database` แล้วตั้ง Script properties `DB_*` ให้ชี้ไฟล์ใหม่
   (เก็บไฟล์ฐานข้อมูลเดิมไว้ ห้ามลบจนตรวจสอบเสร็จ)
3. ลบ Script property `TX_PENDING` ถ้ามี (ธุรกรรมค้างของฐานข้อมูลเดิม) แล้วรัน `setup` เพื่อตรวจโครงสร้าง
4. เปิดการเข้าถึงคืน และบันทึกเหตุการณ์กู้คืน
5. ข้อมูลที่เกิดหลังเวลาสำรองจะหายไป — ตรวจรหัสยืนยันการส่งงานช่วงนั้นกับนักเรียน/ครู

ไฟล์งานไม่ถูกสำรองซ้ำโดยระบบ (อ้างอิง `drive_file_id` เดิม) ไฟล์ที่ถูกลบกู้จากถังขยะ Drive ได้ 30 วัน

## 8. รายการตรวจความปลอดภัยก่อนใช้งานจริง

- [ ] บัญชีระบบเป็นบัญชีของโรงเรียน เปิด 2FA และมีผู้รู้รหัสน้อยที่สุด
- [ ] ไม่มีผู้ใดเป็น editor ของโปรเจกต์ Apps Script / ไฟล์ Sheets นอกจากผู้ดูแลที่ได้รับมอบหมาย
- [ ] ไม่แชร์โฟลเดอร์ระบบ
- [ ] เปลี่ยนรหัสผ่านชั่วคราวของ `admin` แล้ว
- [ ] ติดตั้ง trigger แล้ว (หน้าผู้ดูแลไม่มีคำเตือน) และตรวจว่ามีชุดสำรองเกิดขึ้นทุกวัน
- [ ] ทดสอบคืนค่าบนสภาพแวดล้อมแยกอย่างน้อยหนึ่งครั้ง
- [ ] โรงเรียนยืนยันนโยบาย: ชนิด/ขนาดไฟล์ อายุการเก็บไฟล์ การส่งช้า การยกเว้น เกณฑ์เกรด การปัดเศษ
- [ ] ทดสอบโหลดด้วยจำนวนผู้ใช้จริงบางส่วน (เช่น ทั้งห้องส่งงานพร้อมกัน) ก่อนเปิดใช้ทั้งโรงเรียน
