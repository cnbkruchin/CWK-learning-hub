# ตารางจับคู่ข้อกำหนดกับการออกแบบ โค้ด และผลทดสอบ

สถานะ ณ รอบนี้ (**รอบที่ 2: ทะเบียนนักเรียน กลุ่มประจำรายวิชา สมุดคะแนน คะแนนกลุ่ม และรายงาน PDF/Excel** ต่อจากรอบที่ 1 ระบบจัดเก็บข้อมูลและการส่งงาน)
— ใช้คำว่า "ผ่าน" เฉพาะที่มีการทดสอบอัตโนมัติจริง

> **ข้อสำคัญ**: การทดสอบทั้งหมดรันบน Node.js กับ **บริการ Google จำลอง** (`tests/harness/gas-fakes.js`)
> และหน้าเว็บทดสอบใน Chromium กับเซิร์ฟเวอร์จำลอง **ยังไม่ได้ทดสอบบน Google Apps Script จริง**
> ต้องติดตั้งและทดสอบบนบัญชีจริงก่อนใช้งาน (ดู [06-deployment.md](06-deployment.md))

## 4. สิ่งที่ยังไม่เชื่อม / ยังไม่ทดสอบ / ข้อจำกัดจริง

- ยังไม่ได้ติดตั้งและทดสอบบน Google Apps Script/Sheets/Drive จริง (พฤติกรรมที่ต้องยืนยันบนของจริง: quote prefix ของ Sheets,
  TextFinder บนเซลล์ข้อความ, Drive resumable upload ผ่าน UrlFetchApp, `sha256Checksum` จาก Drive API, การดาวน์โหลด Blob และ `window.print()` ใน iframe ของ HtmlService)
- PDF สร้างด้วยการพิมพ์ของเบราว์เซอร์ (ผู้ใช้กด "พิมพ์" แล้วเลือก "บันทึกเป็น PDF") ยังไม่มีการสร้างไฟล์ PDF ที่เซิร์ฟเวอร์ เลขหน้าในหัว/ท้ายกระดาษใช้ CSS `@page` ซึ่ง Chrome/Edge รุ่นใหม่รองรับ เบราว์เซอร์อื่นอาจไม่แสดงเลขหน้า
- ยังไม่ได้วัดเวลาตอบสนองและจำนวนผู้ใช้พร้อมกัน (เป้าหมายทดสอบ 1,000 นักเรียน / 50 ครู / 100 กลุ่มเรียน) — การซิงก์กลุ่มประจำรายวิชาและการสร้างสมุดคะแนนอ่านหลายตาราง ควรวัดบนของจริง
- รหัสผ่านชั่วคราวที่ระบบสุ่มใช้ PBKDF2 2,000 รอบ (สุ่ม 12 ตัว ≈ 60 บิต และต้องเปลี่ยนเมื่อเข้าใช้ครั้งแรก) เพื่อให้สร้างบัญชีทั้งห้องได้ทันเวลาของ Apps Script; รหัสที่ผู้ใช้ตั้งเองใช้ 60,000 รอบ
- ยังไม่มี: ปิดผลรายวิชา/snapshot ผลสุดท้าย, นำเข้าคะแนน/ครู/รายวิชา, อ่าน XLSX/ODS โดยตรง, หน้าวางแผนหมวด/รุ่นนโยบายคะแนนใหม่, รูบริก, สถานะพิเศษ ร มส มผ, แดชบอร์ดสถิติ, คัดลอกรายวิชา, ย้ายข้อมูลปีเก่า
- ไม่มีการสแกนไวรัส (ตรวจโครงสร้างไฟล์เท่านั้น)
- session เก็บใน CacheService อาจหายก่อนกำหนด → ผู้ใช้ต้องเข้าสู่ระบบใหม่ (ไม่มีข้อมูลสูญหาย)
- การเขียนทั้งหมดผ่านล็อกเดียว ช่วงส่งงานพร้อมกันจำนวนมากต้องรอคิว (หน้าเว็บลองใหม่อัตโนมัติ)
