# ตารางจับคู่ข้อกำหนดกับการออกแบบ โค้ด และผลทดสอบ

สถานะ ณ รอบนี้ (**ระยะที่ 1–2 ส่วนการจัดเก็บข้อมูลและการส่งงาน**) — ใช้คำว่า "ผ่าน" เฉพาะที่มีการทดสอบอัตโนมัติจริง

> **ข้อสำคัญ**: การทดสอบทั้งหมดรันบน Node.js กับ **บริการ Google จำลอง** (`tests/harness/gas-fakes.js`)
> และหน้าเว็บทดสอบใน Chromium กับเซิร์ฟเวอร์จำลอง **ยังไม่ได้ทดสอบบน Google Apps Script จริง**
> ต้องติดตั้งและทดสอบบนบัญชีจริงก่อนใช้งาน (ดู [06-deployment.md](06-deployment.md))

npm run test:e2e  → ผ่าน                (Chromium ผ่าน Playwright กับเซิร์ฟเวอร์จำลอง ขนาดจอมือถือ 390×844 และคอมพิวเตอร์ 1280×860)

## 4. สิ่งที่ยังไม่เชื่อม / ยังไม่ทดสอบ / ข้อจำกัดจริง

- ยังไม่ได้ติดตั้งและทดสอบบน Google Apps Script/Sheets/Drive จริง (พฤติกรรมที่ต้องยืนยันบนของจริง: quote prefix ของ Sheets,
  TextFinder บนเซลล์ข้อความ, Drive resumable upload ผ่าน UrlFetchApp, `sha256Checksum` จาก Drive API, การดาวน์โหลด Blob ใน iframe ของ HtmlService)
- ยังไม่ได้วัดเวลาตอบสนองและจำนวนผู้ใช้พร้อมกัน (เป้าหมายทดสอบ 1,000 นักเรียน / 50 ครู / 100 กลุ่มเรียน)
- ยังไม่มี: นำเข้าข้อมูล, จัดการบัญชี/ทะเบียน, สมุดคะแนน, ประกาศคะแนน, ปิดผล, PDF/XLSX, แดชบอร์ดสถิติ, ย้ายข้อมูลปีเก่า
- ไม่มีการสแกนไวรัส (ตรวจโครงสร้างไฟล์เท่านั้น)
- session เก็บใน CacheService อาจหายก่อนกำหนด → ผู้ใช้ต้องเข้าสู่ระบบใหม่ (ไม่มีข้อมูลสูญหาย)
- การเขียนทั้งหมดผ่านล็อกเดียว ช่วงส่งงานพร้อมกันจำนวนมากต้องรอคิว (หน้าเว็บลองใหม่อัตโนมัติ)
